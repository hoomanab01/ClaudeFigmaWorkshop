## Presenting

Open `presentation.html` in any browser.

| Key | Does |
|---|---|
| `→` `←` | Next and previous slide |
| `N` | Presenter notes: timing, whose segment it is, what to say |
| `F` | Fullscreen |
| `Home` `End` | First and last slide |

Notes are off by default, so the deck is safe to put on a projector before you have switched them on. Nothing loads from the network except web fonts, and the layout holds without them.

## The two things the evening turns on

**Rung four.** One token changes and the whole screen follows, or it does not and the system leaked. Do it on the projector first, in one edit, then send them to do it. Say before they start that either result is a win, because the failure is the more useful lesson and you do not want anyone hiding it.

**The trap reveal.** Do not name either fault until somebody has found one on their own, then credit them. If nobody found them, that is a stronger point rather than a weaker one: neither fault is a model failure, both are handoff failures, and both were theirs to catch.

## If you are short on time

Cut rung two. Never cut rung four.
